# Cyber Watch Map

A rolling seven-day world map of publicly reported cyber events, for defenders. Public, read-only for visitors. Owner: Xander.

Live site: Netlify, built from this repo's `main` branch. Data and page live together in this repo.

## Layout

```
site/index.html          the whole page (styles, markup, script); no framework
site/vendor/             d3 7.9.0 and topojson 3.0.2, served locally (no CDN)
site/world-110m.json     country outlines
site/data/bundle.json    GENERATED by scripts/build.mjs; never edit, never commit
data/events/<id>.json    one file per event (the source of truth)
data/kev/<CVE>.json      CISA known-exploited entries, last 45 days
data/corrections/<id>.json
data/status.json         last-run time per scheduled job, notes, health
data/analysis.json       patterns and chains
data/ripples.json        ripple effects
data/brief.json          daily brief
data/history.json        daily counts for the typical-day baseline
scripts/build.mjs        validates every record and writes the bundle; fails on bad data
tests/test_all.py        browser regression suite; must print ALL PASS
docs/                    data schema and the scheduled-job prompts
netlify.toml             build command, publish folder, security headers
```

## Commands

- `node scripts/build.mjs` — validate `data/` and build the bundle. Exit 1 means a record is broken; the message names the file.
- `python3 tests/test_all.py` — builds, serves `site/` locally and runs the browser checks (needs `pip install playwright` and `playwright install chromium`).
- Preview: `node scripts/build.mjs && python3 -m http.server -d site 8000`.

## Rules for changing the page

1. Every record goes through a `clean*()` function in the script before use. Add new fields there, with length limits.
2. Each panel renders inside `safe()`. Keep it that way so one failure cannot blank the page.
3. Category colours are a validated colour-blind-safe set (light and dark). Category is always shown by shape too. Do not add a hue without re-validating.
4. Charts lead with the question they answer and print their caveats underneath. Bar charts are single-colour; breakdowns go in tooltips.
5. No viewer workflow state. The owner decided visitors do not mark items handled, patched or not relevant.
6. Refresh reloads data and resets to the main map view.
7. Bump `BUILD.version` and `BUILD.date` in the script, run the tests, then commit.

## Rules for data (people and scheduled jobs)

- Facts only from pages actually read. Never invent a document number, finding, quote or URL.
- `sources` are the specific article or advisory URLs read, never a publisher's front page.
- Prefer the original government or vendor document. Record the review in `report` with `read_depth` = `full`, `summary` or `secondary`.
- Outages are category `outage` and are never called attacks unless an official source says so.
- Attacker claims the organisation has not confirmed: `status` `claimed`, `severity` 1. Hidden by default.
- Known-exploited, public exploit code, or an official "patch immediately": severity 3 for widely used or internet-facing software.
- When an original contradicts an entry, fix the entry and add `data/corrections/<date>-<short id>.json`.
- Use the real current time (`date -u +%Y-%m-%dT%H:%M:%SZ`), never an estimate.
- Never delete event files. Mark a duplicate with `"duplicate_of": "<id>"`; the build leaves it out.
- Slow sites: retry after 60 then 120 seconds. Do not work around sites that block automated readers.
- Commit data changes with a message like `data: hourly sweep, 3 new, 2 updated`. Run `node scripts/build.mjs` first; never commit if it fails.

Full field list: `docs/schema.md`. Scheduled job prompts: `docs/jobs.md`.

## Known limits

- Coverage is thin for Africa, Turkey, most of the Middle East and Latin America.
- Attack-surface and sector rows in the analysis views are assigned by keyword and can be wrong.
- Germany's BSI, Australia's cyber.gov.au and SAP notes block automated readers.
- Error reports from visitors arrive as Netlify form submissions (form name `event-report`), not in the repo.
