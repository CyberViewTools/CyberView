# CyberView — file-by-file layout

Reference for the CyberView codebase: what each file, script, data path and workflow is for. Moved out of CLAUDE.md to cut its fixed per-turn cost; the rules themselves stay in CLAUDE.md. Nothing here is a rule change.

## Layout

```
site/index.html, app.js  the globe page (markup and styles; script in app.js so the CSP can forbid inline scripts)
site/nav.js              site navigation on every page: inline links on wide screens, a menu sheet on phones
site/archive.html, .js   the searchable archive of every event on file
site/cve.html, workbench.html, moved.js   thin redirects to vulnerabilities.html (query and hash kept)
site/trends.html, .js    week-over-week trends from site/data/trends.json (styles shared in archive.css)
site/actors.html, .js, .css   threat actor profiles from site/data/actors.json (scripts/actors.mjs at build, no AI model: attributed, named and claimed events kept apart; aliases only from MITRE ATT&CK, config/attack-groups.json, or an event's own text, each with its source); nav.js adds the link to pages written before it
site/status.html, .js    routines and their last runs, lead queue, recent runs (from site/data/ops.json)
site/vulnerabilities.html, .js, workbench-lib.js, cvedb-lib.js, ot-lib.js   the Vulnerabilities page, one page with five views: Known exploited (patch queue ranked with reasons, CISA deadline chart and calendar file, check and fix steps), All CVEs (look up or browse the CVE List from data/cve/ lookup files, joined with the KEV data), My software (the visitor's list matched by version, browser only), Hunt pack (from site/data/workbench.json), Industrial (ICS/OT) (advisories from site/data/ics.json, ranked with every point listed; each CVE elsewhere on the page shows the industrial advisories naming it)
site/community.html, .js  the public community feed (reviewed posts from site/data/chat.json; posting is a GitHub issue form)
site/tabletop.html, .js  the weekly tabletop exercise (from site/data/tabletop.json; facilitator clock, print, copy)
routines.json            registry of every routine: schedule, model, status key, max age, active
config/feeds.json, queries.json   extra feeds and standing searches; the source scout and editor jobs maintain them
config/feeds.d/*.json    the bulk feed lists, one shard per region or sector ({_note, first_run_hours, feeds}); every entry added by scripts/feed-check.mjs
scanner/                 the downloadable vulnerability scanner (docs/scanner.md, scanner/README.md): an operator runs it on their own authorized network; detection only (reads stated versions, never exploits, logs in, guesses passwords/community strings, or floods), refuses to run without a scope file and recorded attestation, public addresses need --i-am-authorized-for-public-ranges and stay under a hard cap, rate/concurrency limits only lowerable (per-host/total budgets scale for owned private ranges), never uploads; optional discovery (scanner/lib/discover.mjs: cidr sweep, owned domains + Certificate Transparency, imported asset lists, read-only cloud inventory JSON — never runs the cloud CLI or reads keys) re-checks every found host against the scope; depth: --all-ports (private ranges only) and --udp (one benign read-only DNS/NTP/SNMP query each, node dgram only in scanner/lib/udp.mjs); matches and rates with site/workbench-lib.js and site/cvedb-lib.js unchanged; offline from a `data` snapshot; opt-in identify hellos (scanner/lib/hello.mjs, --identify, off by default) now also cover Kafka ApiVersions, Redis PING, MQTT CONNECT and MongoDB hello, each one frozen byte sequence built from that protocol's own published specification and locked in REVIEWED_HEX, reporting posture (no Redis password, anonymous MQTT) rather than inventing versions; `match` (scanner/lib/inputs.mjs) produces the same five report files from files the operator already holds (nmap `-oX` with `-sV`, an SBOM, a package list) for assets they cannot scan, contacting nothing at all and saying so in the report, with an inventory that has no address rated internal unless `--assume-exposed`; `lookup <CVE>` (scanner/lib/lookup.mjs) reads one CVE from the same snapshot (rating, both exposure deadlines, NVD ranges, the fix, whether a fingerprint can find the product, and a held version against the ranges), adding no data path; security-check section 7 guards it
site/vendor/             d3 7.9.0 and topojson 3.0.2, served locally, hashes pinned in scripts/security-check.mjs
site/account.js, unsubscribe.js   optional accounts (Supabase); the ONLY pages allowed to load vendor/supabase.min.js and reach the project
legal/*.html, pages/*.html   sources for about/privacy/terms and account/unsubscribe; scripts/pages.mjs renders them into site/ (generated, not committed)
config/site.json, accounts.json   public settings (contact, mailing address, Supabase URL and anon key); never a secret
supabase/migrations/     accounts schema with row-level security; tests/sql/ attacks it (CI job sql-security-tests)
scripts/alerts.mjs       email alerts (alerts.yml; secrets in GitHub only); docs/accounts.md and docs/legal.md explain both
site/logo.svg, *.png     logo (16 x 16 pixel head) and icons
site/data/               GENERATED by scripts/build.mjs (bundle.json and archive/); never edit, never commit
data/                    the data branch, mounted here (a git worktree locally, a second checkout in Actions; main has no data/ and git-ignores the folder). Commit only with finish.mjs or data-commit.mjs
data/events/<YYYY-MM>/<id>.json   one file per event, in the month of its date (the source of truth; never deleted)
data/kev/<CVE>.json      CISA known-exploited entries (full history; the site shows 45 days)
data/context/ioda.json, gdacs.json   map context layers (internet disruption signals, disaster alerts); written by scripts/context.mjs, not cyber events
data/corrections/<id>.json
data/leads/<date>.jsonl  feed items waiting to be checked (q.mjs leads)
data/runs/<date>/<HHMM>-<job>.json   research log of every job run: searches, pages read, added, skipped, open leads
data/snapshots/brief|analysis/<date>.json   daily copies of the brief and the analysis
data/chat/<YYYY-MM>/<issue>.json   reviewed community posts (written only by scripts/chat.mjs approve; pending.json is untracked working state)
data/guides/<CVE>.json   fix guides from vendor advisories (advisory desk; checked by scripts/lib/validate.mjs)
data/tabletop.json, snapshots/tabletop/<date>.json   the weekly tabletop exercise (checked by scripts/lib/validate.mjs)
data/status.json, analysis.json, ripples.json, brief.json, history.json   current single documents
data/evals/cases.jsonl, summary.json   the accuracy test set and its baseline score (scripts/evals.mjs build, written by the improver; never article text)
data/quality.json        the pipeline check's findings (scripts/pipecheck.mjs): stage table, problems with first-seen times, status.json key memory, data size per day, failing feeds
scripts/lib/store.mjs    the one place that knows the data layout
scripts/lib/repo.mjs     where data lives in git: dataMode (data branch or old layout), commitData, pullAll, dispatchDeploy
scripts/data-branch.mjs  the switch: `status`, `create` (once), `ensure` (switches a checkout, carrying uncommitted data over), `forward` (data still pushed to main, for data-forward.yml)
scripts/data-commit.mjs  commit and push data/ paths in either layout, then start the deploy (the data workflows use it)
scripts/propose.mjs      a job's changes to config/ or docs/ as a pull request to main with auto-merge (called by finish.mjs)
scripts/build.mjs        validates every record, writes the bundle and the archive; fails on bad data
scripts/q.mjs            search the whole history without reading files (find, dupes, get, seen, leads, runs, kev, stats)
scripts/feeds.mjs        KEV, EPSS and CVSS feeds (GitHub Action, no AI model)
scripts/cve.mjs          the CVE corpus (no AI model): baseline from the CVE List's midnight release, hourly changes from its deltaLog, EPSS, KEV, and NVD's own CVSS scores and affected-version ranges (`nvd`: a full read is the bounded backfill, then incremental lastMod windows; ranges parsed by `affectedFromNvd` in the same shape the workbench/scanner matcher uses, so the Vulnerabilities page's "My software" and All CVEs views confirm a version for every CVE NVD has analysed, not just KEV; rule 11: ranges come from NVD); `site` writes the lookup files; new notable CVEs become leads. The corpus (cache/cve, ~300,000 rows) lives in the GitHub Actions cache (key cve-corpus-<run>), never in git. cve.yml runs hourly and on any push that changes the CVE code; scripts/cve-baseline.sh rebuilds everything since 1999 on the first run, on request, or when the corpus is older than the change log reaches (`delta` exits 4)
scripts/cve-db.mjs      SUPERSEDED by scripts/cve.mjs (kept for reference; cve-db.yml runs only by hand and the deploy no longer copies it): every CVE NVD has published, compact, sharded by year on the cve-data branch (one force-pushed commit, built by cve-db.yml, copied into site/data/cve/ at deploy); never commit it to main
scripts/grid.mjs         power grid outages, no AI model: 40 public operator and agency feeds (six built in: Hydro-Québec, BC Hydro, UK Power Networks, Eskom, ERCOT, AEMO; the rest are source files in scripts/grid-sources/, one per region group, among them state and national emergency agencies' counts for Pennsylvania, Maryland and Chile in agencies.mjs and Japan's OCCTO reserve in japan.mjs) and three keyed signals -> data/grid/live.json, incidents (open, peak, close) in data/grid/incidents.json and history/<YYYY-MM>.jsonl, the rule pass (which incidents need their cause checked), data/context/grid.json (map context); `verify`, `status`; runs every research cycle, collect.yml as backup; thresholds in config/grid.json
scripts/grid-analysis.mjs   grid analysis, no AI model, every research cycle after grid collect: incidents unusual for the hour of the week (robust z on 4 weeks of 15-minute points in data/grid/series/, 35 days kept, older rolled into series/monthly/), corroboration by independent signals (IODA, GDACS, news leads, and Cloudflare Radar, EIA, ENTSO-E once their keys are saved), 30-day trends per region -> data/grid/analysis.json; a corroborated incident is sent to the grid researchers
scripts/grid-news.mjs    power outages from public news reporting, no AI model: standing queries in 33 languages (config/grid-news.json) on Bing News and GDELT (not Google News: its robots.txt disallows /rss/), false-positive guards, place and stated figures (customers, homes or people, never converted), grouped by place and time -> data/grid/news.json; the Grid view's third tier "reported in the news, not checked", never an incident; counted as a news signal by grid-analysis
scripts/grid-desk.mjs    the grid researchers' queue: `plan` (leases kind grid), `apply` (validates the decision, sources and plan_id, writes data/grid/research.json); an official or credible report of a cyberattack becomes a lead for the normal research loop, never an event directly
scripts/outage-desk.mjs  the outage checkers' queue (role outage, in the research loop, `flow.outage_workers`): unchecked outage reports (news-reported power outages no operator feed or grid desk covers, strong IODA internet disruptions, status-page outages); `plan` (leases kind outage), `apply` (validates and writes data/outages/checks.json: confirmed, not_confirmed or cyber_lead, which becomes a lead, never an event directly); the Grid view and the IODA layer show the check, unchecked reports stay labelled unchecked
scripts/lib/gates.mjs    no-result gates, no AI model, pure functions (owner, 2026-11-23): whether there is anything new for a worker to find before one is started; the wait between two looks at the same item doubles with every look that changed nothing and drops to zero when something new arrives; used by the follow-up, claims and outage desks and the gap pass; every skipped item keeps its reason and the time it is due next (docs/jobs.md "No-result gates")
scripts/followup-desk.mjs  the follow-up desk's planner (in the research loop every `flow.followup_every_minutes`): `plan` hands out only events with new reporting since their last follow-up or whose backoff is over (config/pipeline.json `followup_desk`), in batches of two, severity 3 and exploited ones as followup-deep; `status`; no due event, no worker
scripts/budget.mjs       the shared usage window for work that is not the pipeline: `status`, `can-build` (exit 1 while the 5-hour estimate is above 100 minus `usage_budget.pipeline_reserve_pct`, or the plan refused a pipeline worker in the last hour), `spent` (a build wave's own usage, a local file)
scripts/claims-desk.mjs  the claims checkers' queue (role claims, in the research loop, `flow.claims_workers`, also when usage is tight): ransomware and extortion leak-site claims (leads of kind claim), most notable victim first, skipping claims already matched to an event; `plan` (leases kind claim), `apply` (validates and writes data/claims/checks.json: confirmed_by_victim or reported with the event the checker wrote, denied, unconfirmed (re-checked after `claims_desk.recheck_hours`), not_found); refuses leak sites, .onion and claim trackers as sources and any stolen data in text; events show "Checked by CyberView AI (a Claude model)"
scripts/context.mjs      context layers from IODA and GDACS, run by feeds.yml every 2 h (exports its parsers for tests)
scripts/ics.mjs          industrial (ICS/OT) advisories, no AI model, feeds.yml every 2 h (optional step): CISA ICS/ICSMA and Siemens, Schneider, ABB, Phoenix Contact CSAF, CERT@VDE, Moxa, Mitsubishi Electric RSS (robots.txt read first; Rockwell refuses automated readers) -> data/ics/advisories.json (dials in config/ics.json), joined with KEV; exploited, CVSS 9+ or lifeline-sector ones become leads (kind advisory); the build writes site/data/ics.json
scripts/psirt.mjs        vendor security advisories (PSIRTs), no AI model, feeds.yml every 2 h: Microsoft CVRF API, Cisco, Fortinet, Palo Alto, Red Hat CSAF, Ubuntu, Debian, Oracle, Chrome, Apple, Mozilla, Ivanti (parsers in lib/psirt.mjs, tests with fixtures) -> data/psirt/advisories.json; build.mjs joins it on CVE (site/data/psirt.json) for the Vulnerabilities page, where only the vendor's own "exploited" statement for that CVE raises Exploit Code Maturity (labelled); exploited or critical advisories become leads (kind advisory), never events
scripts/scams.mjs        official scam and phishing warnings by country, no AI model (feeds.yml every 2 h): issuers' own feeds in config/scams.json (government, police, regulators, CERTs) -> data/scams/warnings.json, scam type by a fixed keyword map (labelled keyword-assigned); listed in the Insights tab (#scams), never drawn or counted as events; a warning describing a cyber incident becomes a lead (kind advisory)
scripts/status-pages.mjs service outages from providers' own status pages (cloud, CDN, DNS, SaaS, payment, telecom; config/status-pages.json, each page checked against its robots.txt, skipped ones listed with the reason), no AI model, osint.mjs's cloud-status collector: one lead (kind status, priority = provider tier) per incident with a stated major/critical impact or lasting min_minutes; data/services/status.json feeds the map's Service status list (the provider's own status page, not a cyber event)
scripts/lib/net.mjs      fetch with time limit, retries with backoff, Retry-After honoured on 429/503, and a per-host circuit breaker; use it in new fetchers
scripts/collect.mjs      collects leads from 228 built-in agency, vendor and news RSS and Atom feeds plus config/feeds.json and the shards in config/feeds.d (about 2,500 feeds in all; the `retired` list in feeds.json also switches off a built-in feed and its `watch` list holds low-yield feeds with a review date) into data/leads/<date>.jsonl (research loop and every 30 min, no AI model). At this size each run asks only the feeds that are due (gov every 10 min, vendor 15, news 20; three times less often after 3 days without a lead), most overdue first, host by host (one request at a time per host, 32 hosts at once), with conditional GET, within COLLECT_BUDGET_S (180 s); the rest wait for the next run
scripts/feed-check.mjs   checks candidate feeds before they are added (https, robots.txt allows us, parses, at least 3 dated items, recent, links to the publisher's own site, not a duplicate, at most 4 per host; broad feeds get filter: true) and with --write appends the ones that pass to config/feeds.d/<shard>.json
scripts/osint.mjs        other open sources as leads: Bing News (every standing search in its own language; aggregator copies such as msn.com dropped) and GDELT (config/queries.json; Google News is not collected: its robots.txt disallows /rss/), HIBP, ENISA EUVD, NVD, ransomware.live claims, Hacker News, cloud status; `exploits` writes data/exploits.json
scripts/x-leads.mjs      X (Twitter) as a LEAD SOURCE only, no AI model (collect.yml optional step): Phase 1 ingests candidate leads Grok Bot files as a JSON batch on an `x-leads` GitHub issue (Route B, no X API spend; Route A with X_BEARER_TOKEN is a dormant switch) -> leads in data/leads/<date>.jsonl with `via: "x"`, dedup by x_post_id/url, health in data/x-leads.json, heartbeat last_x_leads_at written every run. Curated accounts in config/x-accounts.json (looked-up handles only; `watch` list never polled), keyword queries in config/x-queries.json (off by default). A post is never an event source and never enough to verify an event: x.com is blocked in event `sources` (SOCIAL_SRC in scripts/lib/validate.mjs, LEAK_HOST in claims-desk.mjs); researchers open the post's cited official page (`linked_url`). Any public X layer is a later, separate decision (Phase 3)
scripts/breaches.mjs     official breach notification registers, no AI model (run by osint.mjs, each at most hourly): California, Washington and Iowa attorneys general, UK ICO enforcement, SEC 8-K Item 1.05 (idle until config/site.json contact_email is set) -> leads of kind "breach-notice", tier gov; health in data/breaches.json
scripts/gdelt-gkg.mjs    GDELT 2.0 knowledge graph 15-minute files from data.gdeltproject.org (plain downloads, no rate limit; English and 65 machine-translated languages), no AI model: each file read once (catch-up after a gap, capped), rows kept by cyber theme plus a cyber headline (config/gdelt.json), filed as leads (via gdelt-gkg) with the publisher's own https page, title, language and first country; state data/gdelt-gkg.json; every research cycle, collect.yml as backup. Replaces the GDELT DOC API (osint `gdelt`, grid-news gdelt_queries) after a clean week (2026-11-28)
scripts/fuse.mjs         groups leads into stories ranked by corroboration, publication age and type (list, show, done); `developing()` feeds the app's "being checked" list; data/stories.json is untracked working state
scripts/analyst.mjs      the exploit analyst's queue: which workbench flaws need an exploitation and remediation analysis, most urgent first
scripts/git-sync.mjs     push after a commit (to the data branch once ./data is mounted, then start the deploy), merging status.json and lead files that several jobs write at once
scripts/backlog.mjs      the research queue kept at zero: `auto` closes what a rule can decide, `plan` and `apply` drive the backlog desk (triagers sort headlines, researchers take the rest), `status` feeds the status page and the guard
scripts/run-job.mjs      runs one scheduled job with headless workers (model, turn cap and tools per role from config/models.json; git denied) and logs every worker's cost to data/usage/<month>.jsonl
scripts/improve.mjs      continuous improvement: report (cost, yield, quality, speed) and bounded, logged changes to config/pipeline.json and config/models.json; the daily improver job decides
scripts/swarm.mjs        catch-up runs over a whole queue: freeze, frozen batches with a plan_id, validate, retry missing, report
scripts/metrics.mjs      pipeline metrics for the editor job and the status page
scripts/updates.mjs      new reporting on published events (no AI model): leads that match an event, from pages it does not cite, newer than its last update; `plan` hands them to updaters in the research loop, `done` records each page as updated, unchanged, unrelated or unreachable (retried once, then dropped)
scripts/classify.mjs     one-off backfill of event `sectors` and `surface` (fixed lists in scripts/lib/taxonomy.mjs): plan (frozen batches with a plan_id), show, run (classifier workers), apply (checked, dry run first), compare (keyword against explicit)
scripts/review.mjs       second review of new events: queue with mechanical flags, and pass, corrected, flagged verdicts (the review desk job); `errors` counts corrections by type and by writer role and model
scripts/evals.mjs        accuracy evals for the event writers, no AI model: `build` turns every second review into a case (the record as its writer left it from the data branch's history, the reviewer's diff, correction types, the specific mistake, writer role and model, the sources; `--out`, default cache/evals/, the improver writes data/evals/), `report` (correction rate by type, role, model and category; the 10 most frequent specific mistakes with example ids, before/after, and whether a mechanical check caught them; `--md` prints the "most common corrections" lines of docs/jobs.md), `propose-checks` (rules a script can decide, each with its measured precision; the good ones are warnings in `proposedProblems`, scripts/lib/validate.mjs, the rejected ones stay listed), `score --events` (every mechanical check over a set of records, plus agreement with the reviewed record: compare a candidate prompt or model with the baseline, no AI judge); improve.mjs report carries it as `evals`
scripts/lib/routing.mjs  which work runs on the deep (Opus) roles: deep stories in sweep-plan.mjs, deep events in updates.mjs and the follow-up desk
scripts/chat.mjs         community feed intake (fixed rules), approve, reject, remove; the moderator job decides
scripts/verify-build.mjs build verifier: outputs parse and match site/data/manifest.json; --against-live refuses a shrunken dataset; --live proves the deploy took
scripts/guard.mjs        end-to-end guard from the outside (live site + public GitHub API): data age, last runs, every stage's heartbeat (health.json stages), the pipeline check's problems, the monitor's last run, deploy lag; --heal restarts what it can
scripts/lib/stages.mjs   every pipeline stage and where its heartbeat lives (status.json key or file), limits from routines.json max_age_hours; read by the build (health.json stages), the guard and the pipeline check
scripts/pipecheck.mjs    pipeline check, no AI model, hourly (pipecheck.yml): late stages (heal restarts their workflow), status.json keys vanishing, missed duplicates, events unreviewed over 2 h, lead files and data growing abnormally, failing feeds and collectors, failing targets -> data/quality.json (the status page's "What needs attention"); `alerts` opens one GitHub issue per lasting problem (label pipeline-alert) and closes it when healthy; `propose-feeds` (the scout) moves feeds failing 7 days to config/feeds.json watch
scripts/lib/backoff.mjs  source health: 3 failures in a row = "failing", asked again only after a backoff (30 min doubling, at most 12 h, never before a Retry-After); collect.mjs and osint.mjs use it
site/sw.js               offline copy: network first, last good copy when the site cannot be reached (registered by nav.js)
scripts/monitor.mjs      live site check (GitHub Action, hourly)
scripts/security-check.mjs   static security check (every code push and weekly)
scripts/job-prompt.mjs   prints a scheduled AI job's full prompt from docs/jobs.md (workers get their assignment with --batch)
scripts/dispatch.mjs     what the ops session runs for every scheduled job: plans the work and says which subagents to start
scripts/grok-watch.mjs   no AI model: surfaces the `[Grok]` issues/briefs (Grok has no GitHub account; its briefs are relayed as [Grok]-titled issues) with what is still unhandled, so Claude (the lead) can act; writes nothing, Grok's briefs are proposals a person still gates
scripts/sweep-plan.mjs   assigns stories to the sweep's researchers by rule and scores the run afterwards (config/pipeline.json sets how many)
scripts/finish.mjs       mechanical end of a job: timestamp, build, commit data to the data branch, push (starts the deploy); config/ and docs/ changes go to propose.mjs
tests/test_all.py        browser regression suite, served with the production headers; must print ALL PASS
tests/unit/*.test.mjs    unit tests (node --test, no dependencies)
tests/smoke_live.py      browser check of the live site
.github/workflows/       pages.yml (deploy), build.yml (code pushes), collect.yml, feeds.yml, cve.yml (CVE corpus, hourly), pipecheck.yml (pipeline check, hourly), monitor.yml, security.yml, data-forward.yml (safety net: anything that still lands under data/ on main is moved onto the data branch), ai-launch.yml (starts the scheduled AI jobs with dispatch.mjs --exec on a runner once vars.AI_LAUNCH is "actions"; signs in with the CLAUDE_CODE_OAUTH_TOKEN subscription secret), ai-jobs.yml (manual fallback only); data workflows check out main without data/ and mount the data branch with .github/actions/data
Claude jobs             run as Claude Code scheduled tasks "CyberView: <job>" in the "CyberView ops" session (see docs/jobs.md)
docs/                    data schema (schema.md) and the scheduled jobs (jobs.md)
```
