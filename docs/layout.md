# CyberView — file-by-file layout

Reference for the CyberView codebase: what each file, script, data path and workflow is for. Moved out of CLAUDE.md to cut its fixed per-turn cost; the rules themselves stay in CLAUDE.md. Nothing here is a rule change.

## Layout

```

site/nav.js              site navigation on every page: inline links on wide screens, a menu sheet on phones
site/doc.js              About, Privacy, Terms and Tools (laid out by docLayout/DOC_PAGES in scripts/pages.mjs): the page's own search and the "On this page" contents rail

Also shows CyberView AI's work, read from site/data/library/ (cards/<xx>.json, stories/<key>.json, stories.json) and site/data/orkl.json counts: a read report's summary and facts (row flag k), a cited story on an actor (row field st) or on a group of reports (#story=<key>), and a Featured reads band after the page heading and above the section strip (hidden until a story is published), and a Report an error link on every summary and story; every fetched record is cleaned again in the page script. Sectors: finance (banks, central banks, financial regulators and payment networks), infra (critical-infrastructure operators and regulators: energy, water, telecoms, transport, health), crypto (crypto security firms, auditors and exchanges' own notices), gov, regulators, psirt, vendors-intl, status (providers' status pages), research, blogs, cybernews, specialist, sectors, trade
scanner/                 the downloadable vulnerability scanner (docs/scanner.md, scanner/README.md): an operator runs it on their own authorized network; detection only (reads stated versions, never exploits, logs in, guesses passwords/community strings, or floods), refuses to run without a scope file and recorded attestation, public addresses need --i-am-authorized-for-public-ranges and stay under a hard cap, rate/concurrency limits only lowerable (per-host/total budgets scale for owned private ranges), never uploads; optional discovery (scanner/lib/discover.mjs: cidr sweep, owned domains + Certificate Transparency, imported asset lists, read-only cloud inventory JSON — never runs the cloud CLI or reads keys) re-checks every found host against the scope; depth: --all-ports (private ranges only) and --udp (one benign read-only DNS/NTP/SNMP query each, node dgram only in scanner/lib/udp.mjs); matches and rates with site/workbench-lib.js and site/cvedb-lib.js unchanged; offline from a `data` snapshot; opt-in identify hellos (scanner/lib/hello.mjs, --identify, off by default) now also cover Kafka ApiVersions, Redis PING, MQTT CONNECT and MongoDB hello, each one frozen byte sequence built from that protocol's own published specification and locked in REVIEWED_HEX, reporting posture (no Redis password, anonymous MQTT) rather than inventing versions; `match` (scanner/lib/inputs.mjs) produces the same five report files from files the operator already holds (nmap `-oX` with `-sV`, an SBOM, a package list) for assets they cannot scan, contacting nothing at all and saying so in the report, with an inventory that has no address rated internal unless `--assume-exposed`; `lookup <CVE>` (scanner/lib/lookup.mjs) reads one CVE from the same snapshot (rating, both exposure deadlines, NVD ranges, the fix, whether a fingerprint can find the product, and a held version against the ranges), adding no data path; security-check section 7 guards it

supabase/migrations/     accounts schema with row-level security; tests/sql/ attacks it (CI job sql-security-tests)

site/logo.svg, *.png     logo (16 x 16 pixel head) and icons

site/data/library/stories/<key>.json   one reviewed story (headline, in short, sections with cited sentences, the cited reports as `src`); from `live` only, never a draft

data/events/<YYYY-MM>/<id>.json   one file per event, in the month of its date (the source of truth; never deleted)
data/kev/<CVE>.json      CISA known-exploited entries (full history; the site shows 45 days)

data/corrections/<id>.json

data/leads/<date>.jsonl  feed items waiting to be checked (q.mjs leads)
data/runs/<date>/<HHMM>-<job>.json   research log of every job run: searches, pages read, added, skipped, open leads
data/snapshots/brief|analysis/<date>.json   daily copies of the brief and the analysis

data/guides/<CVE>.json   fix guides from vendor advisories (advisory desk; checked by scripts/lib/validate.mjs)
data/tabletop.json, snapshots/tabletop/<date>.json   the weekly tabletop exercise (checked by scripts/lib/validate.mjs)
data/status.json, analysis.json, ripples.json, brief.json, history.json   current single documents
data/evals/cases.jsonl, summary.json   the accuracy test set and its baseline score (scripts/evals.mjs build, written by the improver; never article text)
data/quality.json        the pipeline check's findings (scripts/pipecheck.mjs): stage table, problems with first-seen times, status.json key memory, data size per day, failing feeds

scripts/lib/repo.mjs     where data lives in git: dataMode (data branch or old layout), commitData, pullAll, dispatchDeploy

scripts/data-commit.mjs  commit and push data/ paths in either layout, then start the deploy (the data workflows use it)

scripts/q.mjs            search the whole history without reading files (find, dupes, get, seen, leads, runs, kev, stats)
scripts/feeds.mjs        KEV, EPSS and CVSS feeds (GitHub Action, no AI model)
scripts/cve.mjs          the CVE corpus (no AI model): baseline from the CVE List's midnight release, hourly changes from its deltaLog, EPSS, KEV, and NVD's own CVSS scores and affected-version ranges (`nvd`: a full read is the bounded backfill, then incremental lastMod windows; ranges parsed by `affectedFromNvd` in the same shape the workbench/scanner matcher uses, so the Vulnerabilities page's "My software" and All CVEs views confirm a version for every CVE NVD has analysed, not just KEV; rule 11: ranges come from NVD); `site` writes the lookup files; new notable CVEs become leads. The corpus (cache/cve, ~300,000 rows) lives in the GitHub Actions cache (key cve-corpus-<run>), never in git. cve.yml runs hourly and on any push that changes the CVE code; scripts/cve-baseline.sh rebuilds everything since 1999 on the first run, on request, or when the corpus is older than the change log reaches (`delta` exits 4)
scripts/cve-db.mjs      SUPERSEDED by scripts/cve.mjs (kept for reference; cve-db.yml runs only by hand and the deploy no longer copies it): every CVE NVD has published, compact, sharded by year on the cve-data branch (one force-pushed commit, built by cve-db.yml, copied into site/data/cve/ at deploy); never commit it to main

scripts/grid-news.mjs    power outages from public news reporting, no AI model: standing queries in 33 languages (config/grid-news.json) on Bing News and GDELT (not Google News: its robots.txt disallows /rss/), false-positive guards, place and stated figures (customers, homes or people, never converted), grouped by place and time -> data/grid/news.json; the Grid view's third tier "reported in the news, not checked", never an incident; counted as a news signal by grid-analysis
scripts/grid-desk.mjs    the grid researchers' queue: `plan` (leases kind grid), `apply` (validates the decision, sources and plan_id, writes data/grid/research.json); an official or credible report of a cyberattack becomes a lead for the normal research loop, never an event directly
scripts/outage-desk.mjs  the outage checkers' queue (role outage, in the research loop, `flow.outage_workers`): unchecked outage reports (news-reported power outages no operator feed or grid desk covers, strong IODA internet disruptions, status-page outages); `plan` (leases kind outage), `apply` (validates and writes data/outages/checks.json: confirmed, not_confirmed or cyber_lead, which becomes a lead, never an event directly); the Grid view and the IODA layer show the check, unchecked reports stay labelled unchecked
scripts/lib/gates.mjs    no-result gates, no AI model, pure functions (owner, 2026-11-23): whether there is anything new for a worker to find before one is started; the wait between two looks at the same item doubles with every look that changed nothing and drops to zero when something new arrives; used by the follow-up, claims and outage desks and the gap pass; every skipped item keeps its reason and the time it is due next (docs/jobs.md "No-result gates")
scripts/followup-desk.mjs  the follow-up desk's planner (in the research loop every `flow.followup_every_minutes`): `plan` hands out only events with new reporting since their last follow-up or whose backoff is over (config/pipeline.json `followup_desk`), in batches of two, severity 3 and exploited ones as followup-deep; `status`; no due event, no worker
scripts/budget.mjs       the shared usage window for work that is not the pipeline: `status`, `can-build` (exit 1 while the 5-hour estimate is above 100 minus `usage_budget.pipeline_reserve_pct`, or the plan refused a pipeline worker in the last hour), `spent` (a build wave's own usage, a local file)
scripts/claims-desk.mjs  the claims checkers' queue (role claims, in the research loop, `flow.claims_workers`, also when usage is tight): ransomware and extortion leak-site claims (leads of kind claim), most notable victim first, skipping claims already matched to an event; `plan` (leases kind claim), `apply` (validates and writes data/claims/checks.json: confirmed_by_victim or reported with the event the checker wrote, denied, unconfirmed (re-checked after `claims_desk.recheck_hours`), not_found); refuses leak sites, .onion and claim trackers as sources and any stolen data in text; events show "Checked by CyberView AI (a Claude model)"
scripts/context.mjs      context layers from IODA and GDACS, run by feeds.yml every 2 h (exports its parsers for tests)
scripts/ics.mjs          industrial (ICS/OT) advisories, no AI model, feeds.yml every 2 h (optional step): CISA ICS/ICSMA and Siemens, Schneider, ABB, Phoenix Contact CSAF, CERT@VDE, Moxa, Mitsubishi Electric RSS (robots.txt read first; Rockwell refuses automated readers) -> data/ics/advisories.json (dials in config/ics.json), joined with KEV; exploited, CVSS 9+ or lifeline-sector ones become leads (kind advisory); the build writes site/data/ics.json
scripts/orkl.mjs         ORKL threat-report library mirror (the mirror uses no AI model; the Library reports job below is separate), feeds.yml every 2 h (optional step): ORKL's public REST API (orkl.eu/api/v1) -> data/orkl/reports/<shard>.json (sharded by sha1), data/orkl/threat-actors.json and data/orkl/state.json; metadata and links only (title, authors, date, language, sources, named actors, report-page and archive.orkl.eu PDF/text links), never the report body, which only the Library reports job reads, in passing and never stored; first run backfills the whole library newest-first (run by hand), later runs add only what is new; writes no leads and is never a source for an event; the build writes site/data/orkl.json for the status page
scripts/lib/library-check.mjs   pure checks for the Library's fact cards and stories (no AI model, no I/O): quote matching tolerant of PDF noise, `cleanCard`/`cleanStory`, `cardProblems` (every fact quote must be in the report text and hold its value; no code; no link, domain or email address in the summary or a fact value) and `storyProblems` (a headline and an in-short line; every sentence backed by a cited card or the actor catalogue, countries and nationalities from library-countries.mjs included; no bare state attribution), `countriesIn`
scripts/lib/oneshot.mjs   the Library's no-tools, one-turn `claude -p` caller (`oneShot`, `oneShotArgs`, `parseReply`, `ledgerFor`): same worker environment, API-key fallback decision and usage ledger as run-job.mjs, never logs the prompt; its ledger line keeps no reply text (`last` is empty and `error` a short code: timeout, exit-<n>, turn-cap, api-error, no-json; a usage limit is the fixed string "usage limit reached" with `limit_until` kept, so `limitHits` and the budget check count it)
scripts/lib/library-countries.mjs   pure data for the Library's story checks: every UN member state plus common short forms and a few places often named in threat reports, with demonyms (`COUNTRIES`), and `AMBIGUOUS` names (Chad, Georgia, Jordan, Turkey ...) that count only next to a state word; a country or nationality a story names must be held by a cited card or the cited catalogue record
scripts/lib/library-prompts.mjs   pure prompt builders for the Library's reader, writer, reviewer and auditor desks; the document is wrapped in per-call random markers and labelled as data
scripts/lib/orkl-text.mjs   fetches one ORKL report's text for the reader desk (the archive.orkl.eu text file first, then the API entry's plain_text; one at a time through net.mjs) and `prepText` (control characters stripped, capped at 120,000 characters, partial flag); text under 400 characters from the archive falls through to the API entry; the text is never stored
scripts/library-read.mjs   the Library's reader desk (`run --max N --owner-override` by hand, `status`; the desk calls it in-process): fetches each ORKL report's text, Haiku (library-reader, no tools) turns it into a fact card, the card is checked against the text (library-check.mjs), and only the card is written to data/orkl/cards/<shard>.json (read, no-text or unread, tried twice at most; a no-text card is read once more after 30 days); ORKL unreachable, a usage limit or a failed model call leaves the record queued, and unreachable or failed calls are counted per record in data/orkl/read-state.json (last in the queue from 3, parked 7 days at 6); a run where 80% or more of at least 5 answered reports had no text writes no no-text card ("ORKL text missing"); the count is a `noTextGuard`, the run's own or the one the desk shares across its reader calls and settles with `settleNoText`
scripts/lib/library-subjects.mjs   pure: what gets a Library story (no I/O): `actorSubjects` (every ORKL actor, with or without read reports; an alias two actors share joins neither), `looseSubjects` (unattributed reports whose cards hold at least 3 facts, grouped by subject), `basedOn` (hash of the read cards and the actor's aliases and tools; marks a story stale when it changes)
scripts/library-write.mjs   the Library's writer desk (`run --max N --owner-override` by hand, `status`; the desk calls it in-process): Sonnet (library-writer, no tools) drafts each story from fact cards, `storyProblems` checks it, and it is stored only in the `next` slot of data/orkl/stories/<key>.json ({live, next}); it never publishes and only marks `live` stale; a rejected draft is retried once then parked; a usage limit or failed model call writes nothing; an unreadable story file is never written over
scripts/lib/library-audit.mjs   the Library's reader accuracy gate and correction counts (no AI model, shared by the reader, writer and review desks so none imports another): `DEFAULTS` (config/pipeline.json `library`: reread 3, audit_pct 100, audit_pause_pct 5, audit_min 50), `retiredAfterAudit` (cards found wrong twice, not read again; counted by the pipeline check), `auditState`/`paused` over the most recent 500 audited cards, each counted once by the auditor's latest verdict (a reviewer's flag does not count); while paused the writer and review `run` stop, the reader reads only cards an audit found wrong, and each prints "Library reader accuracy below target" (`pauseHelp` says how it clears), and `libraryErrorReport`/`loadCorrections` for `node scripts/review.mjs errors` (a separate Library block)
scripts/library-review.mjs   the Library's review desk and reader audit, no AI model of its own (`run --max N`, `audit --max N`, both need `--owner-override` by hand; `status`; `withdraw <story key | sha1> --reason "<text>"`, the owner's way to take a story or a summary off the site; the only way a story becomes `live`): `run` has Sonnet (library-reviewer, no tools, a separate call from the writer's) check each draft against its fact cards and the freshly re-read most-cited originals (never stored or logged); `settle` takes the reviewer's story as text only, carries every script-owned field from the draft and runs the writer's `storyProblems` again, so a reviewer cannot publish what the checks refuse; a `corrected` story is stored as a new draft for a later run to review (never published by the run that corrected it; a third correction is rejected), and a reject counts toward the writer's two tries. `audit [--pilot]` has Sonnet (library-auditor) re-check a share of the Haiku reader's cards (every card with `--pilot` or while paused; a card read again after a failed audit is always re-audited); a card found wrong by it or by the reviewer is set back to `unread` (`audit.ok` false; retired when it had failed an audit before) and every live story citing it is marked stale with reason card-wrong at once (the site hides it until a rewrite passes). Corrections go to data/orkl/corrections/<story key or card sha1>.json (role library-writer or library-reader, with the model that wrote it)
scripts/library-desk.mjs   the Library's desk runner (`run`, `status`, `pilot-report`; routine `library`, on since 2026-11-26 and run on GitHub Actions by ai-launch.yml; `node scripts/dispatch.mjs library` runs it through scripts/run-job.mjs): decides each run how much to read, write, review and audit: the pilot set first (data/orkl/pilot.json, `pilotComplete` is computed from stored state), then only new reports and stale stories, the backlog only when `library.backfill` is set in config/pipeline.json, billing only the API key within `library.api.monthly_usd_cap` (scripts/run-job.mjs `libraryServedNow`; it never uses the subscription, so the map pipeline's window is untouched), with `library.concurrency` calls in flight per stage; runs review, audit, write, read in waves bound by the time left (the read and write queues restricted to its own orders, review to the pilot's stories until the pilot latches), chooses the pilot only after the mirror's first full pass, gives every reader call of a run one shared no-text counter (the reader is called 4 at a time, the "ORKL text missing" rule needs 5) and writes the run's held no-text cards at the end of the read stage only if the rule was never met, stamps `last_library_at`, writes a run log in data/runs/ (counts and stop codes only), and exports `libraryHealth` (pipecheck) and `libraryBlock` (efficiency.json `library`)
```
